# Hosted MCP preparation

The Cloudflare adapter is a restricted team-pilot foundation. Hosted protocol/search checks pass; customer access and public launch remain gated. The MCP will be a paid, credit-based feature of the future shared Inspora Pro plans. Request limits and OAuth are not a credit ledger.

From `tools/inspora-mcp`, run `npm ci`, then `npm run test:cloudflare` or `npm run cloudflare:check`.
The latter only bundles a dry run; it does not provision resources or publish a Worker. After bundling, `npm run cloudflare:test-runtime` checks the actual local workerd runtime with local R2 and SQLite Durable Objects. It uses fixture embeddings/reference searches, not paid or real Workers AI inference.

The endpoint uses the existing pinned MCP SDK's Web Standards HTTP transport. It shares the existing filtering, result bounds, reference validation and hybrid ranking. Workers AI supplies BGE embeddings; all document vectors must be rebuilt with the exact model/pooling/preparation in `embeddings.mjs`. Local MiniLM vectors are incompatible. Long text is chunked, embedded and combined, not silently clipped to the model token limit.

An immutable complete index is stored under `mcp/hosted/v1/indexes/` in a **private** R2 bucket. `current.json` selects the version. Each request checks the shared pointer; it never calls the website feed or database. Unchanged content reuses cached vectors/indexes. `CatalogSync` serializes publishers, coalesces notifications for five seconds and repairs missed events every twelve hours, as selected by the user. Known edits fence reads until current source metadata/eligibility is captured; changed works are omitted while embeddings are pending. Failed jobs retry with backoff. Last source verification older than twelve hours plus a one-minute scheduling margin fails closed. Input captures themselves must be no older than three minutes. Direct database changes or lost website notifications can wait for the shared repair. This freshness tradeoff must remain visible at launch.

Continuation is persisted transactionally in a SQLite Durable Object per principal, preserving query binding, single use, expiry and snapshot invalidation across requests/restarts. There is no global object serializing all searches. Pilot limits are 30 MCP requests/minute and 500/day per principal, with a 16 KB request bound. These limits are not an account-wide spending cap.

Selected `get_work` image requests can attach a prepared PNG up to 256 KB from private R2, keyed by the current media fingerprint. Search results do not download thumbnails. Missing or changed media falls back to its public link; no arbitrary external fetch occurs. Client rendering still needs testing. The publisher also sweeps up to 100 old index versions every twelve hours, retaining the current version and versions newer than two days, with a persistent sweep cursor. Maintenance never runs on the search path.

Deployment intentionally defaults to disabled access, no workers.dev URL and no public preview URLs. Configure an exact `MCP_ORIGIN`, private `CATALOG` R2, `AI`, SQLite `ACCESS_STATE`/`CATALOG_SYNC`/`AUTH_TICKETS`, and `OAUTH_KV`. OAuth mode uses PKCE, browser-bound consent, server identity exchange with the website's existing Clerk session, scoped tokens and revocation. The website currently authorizes only its team allowlist. Unsupported access-policy flags fail closed; customer access must later use shared Pro entitlements and transactional credits. `ACCESS_MODE=pilot` plus expiring independently hashed tokens remains a temporary agent-test mechanism. Never reuse the catalog-source token for client access. No tokens or environment files belong in Git.

Readiness checks include actual website-to-Worker notifications, edit/removal/outage recovery, selected previews, hosted OAuth/Clerk connection, bounded Claude/Codex client tests and two-machine team trials. Human usefulness acceptance is separate. Public release additionally requires Pro entitlement/credit integration, agreed credit rules and launch approval. The exact full-catalog ranking is retained rather than silently capping discovery at Vectorize's top-K; optimize further only with evidence from retrieval quality, CPU/memory and concurrency measurements.

Maintainer comparison: after plan/spend confirmation, set the verified `CLOUDFLARE_ACCOUNT_ID`, load the local catalog-only environment and run `node cloudflare/evaluate-managed.mjs`. It captures Wrangler's current token internally (or uses a scoped `CLOUDFLARE_API_TOKEN`), never prints credentials, refreshes the catalog once and stores the candidate index/comparison under ignored scratch data. The 200-request safety bound is not a dollar cap. Six supplemental website/design requests accompany the existing 20 cases. A real hosted/client latency test and human relevance review are separate.

**Subscription readiness:** the user confirmed the existing Workers Paid plan used by Databull on the same account. Its $5/month base is shared; no additional subscription is required for this Worker. Check plan readiness before public launch or if moving accounts, and measure incremental usage separately. Preserve Databull and account billing settings. Public launch and the MCP website page remain behind their existing release gates. Uploaded reference images remain Phase 2.
