# Hosted MCP preparation

The Cloudflare adapter is a restricted team-pilot foundation. Hosted protocol/search checks pass; customer access and public launch remain gated. The MCP will be a paid, credit-based feature of the future shared Inspora Pro plans. Request limits and OAuth are not a credit ledger.

From `tools/inspora-mcp`, run `npm ci`, then `npm run test:cloudflare` or `npm run cloudflare:check`.
The latter only bundles a dry run; it does not provision resources or publish a Worker. After bundling, `npm run cloudflare:test-runtime` checks the actual local workerd runtime with local R2 and SQLite Durable Objects. It uses fixture embeddings/reference searches, not paid or real Workers AI inference.

The endpoint uses the existing pinned MCP SDK's Web Standards HTTP transport. It shares the existing filtering, result bounds, reference validation and hybrid ranking. Workers AI supplies BGE embeddings; all document vectors must be rebuilt with the exact model/pooling/preparation in `embeddings.mjs`. Local MiniLM vectors are incompatible. Long text is chunked, embedded and combined, not silently clipped to the model token limit. Similarity gates are per model (`SEMANTIC_GATES` in `search.mjs`): BGE scores the whole catalog around 0.55–0.65, so MiniLM thresholds would admit every work. Recalibrate the gates whenever the embedding model changes.

An immutable complete index is stored under `mcp/hosted/v1/indexes/` in a **private** R2 bucket. `current.json` selects the version. Each request checks the shared pointer; it never calls the website feed or database. Unchanged content reuses cached vectors/indexes. `CatalogSync` serializes publishers, coalesces notifications for five seconds and repairs missed events every twelve hours, as selected by the user. Known edits fence reads until current source metadata/eligibility is captured; changed works are omitted while embeddings are pending. Failed jobs retry with backoff. Last source verification older than twelve hours plus a one-minute scheduling margin fails closed. Input captures themselves must be no older than three minutes. Direct database changes or lost website notifications can wait for the shared repair. This freshness tradeoff must remain visible at launch.

Continuation is persisted transactionally in a SQLite Durable Object per principal, preserving query and principal binding, expiry and snapshot invalidation across requests/restarts. It stores only the next 1,000 ranked ids with deduplicated labels; a capped continuation ends with `continuation_limited`. Re-reading a cursor with the same page settings returns the same page and next cursor; the local stdio server derives next cursors the same way. At the 128-entry cap the earliest-expiring cursor is evicted. There is no global object serializing all searches. Each person has 30 tool calls/minute and 500/day across all clients; a refused call is a readable tool error with `retry_after` and `limit_window`. Protocol traffic (initialize, notifications, tools/list, ping) does not spend that budget; all requests share an HTTP abuse ceiling of 60/minute and 1,000/day (HTTP 429 only when no tool result is possible), with a 16 KB request bound. These limits are not an account-wide spending cap.

`catalog_status` always answers and reports `catalog_state` (`ready`, `updating` with `retry_after_seconds`, `stale` or `unavailable`). Search and details fail closed while a known edit is pending, because website notifications name no works and the previous snapshot could still show a removed work. The fence lifts as soon as a build whose source read began after the latest edit publishes; embedding work finished during newer edits is kept, and a failing source is retried at least once a minute while reads are fenced. Steady edit bursts still pause reads until they stop; sending edited work IDs in notifications would allow serving the previous snapshot minus those works (website follow-up).

For eligible works with prepared visuals, `get_work` returns a still by default and `detail=study` includes the available timestamped motion sheets. `get_works` batches up to six works and also accepts `detail=study`. Image data is bounded to 900,000 bytes per response counted after base64 encoding, so the whole reply stays under 1 MB. Assets that do not fit are reported (`budget_reached`, `omitted_roles`, partial `preview.study`) rather than replaced. A study set that does not fit drops the duplicate lower-resolution overview first when the still and all detail sheets then fit. Each image follows a text label and is tied to the exact work and media fingerprint. The Worker reads prepared files from private R2 and falls back to the legacy thumbnail or public link only when no valid pack exists. Search still returns compact text. See the [local preparation workflow](../MAINTAINER.md#prepare-work-visuals).

The publisher sweeps up to 100 old index versions every twelve hours, retaining the current version and versions newer than two days, with a persistent sweep cursor. The index sweep does not manage visual artifacts. Plan visual storage cleanup before a full backfill.

Deployment intentionally defaults to disabled access, no workers.dev URL and no public preview URLs. Configure an exact `MCP_ORIGIN`, private `CATALOG` R2, `AI`, SQLite `ACCESS_STATE`/`CATALOG_SYNC`/`AUTH_TICKETS`, and `OAUTH_KV`. OAuth mode uses PKCE, browser-bound consent, server identity exchange with the website's existing Clerk session, scoped tokens and revocation. The website currently authorizes only its team allowlist. Unsupported access-policy flags fail closed; customer access must later use shared Pro entitlements and transactional credits. `ACCESS_MODE=pilot` plus expiring independently hashed tokens remains a temporary agent-test mechanism. Never reuse the catalog-source token for client access. No tokens or environment files belong in Git.

Readiness checks include actual website-to-Worker notifications, edit/removal/outage recovery, selected previews, hosted OAuth/Clerk connection, bounded Claude/Codex client tests and two-machine team trials. Human usefulness acceptance is separate. Public release additionally requires Pro entitlement/credit integration, agreed credit rules and launch approval. The exact full-catalog ranking is retained rather than silently capping discovery at Vectorize's top-K; optimize further only with evidence from retrieval quality, CPU/memory and concurrency measurements.

Maintainer comparison: after plan/spend confirmation, set the verified `CLOUDFLARE_ACCOUNT_ID`, load the local catalog-only environment and run `node cloudflare/evaluate-managed.mjs`. It captures Wrangler's current token internally (or uses a scoped `CLOUDFLARE_API_TOKEN`), never prints credentials, refreshes the catalog once and stores the candidate index/comparison under ignored scratch data. The 200-request safety bound is not a dollar cap. Six supplemental website/design requests accompany the existing 20 cases. A real hosted/client latency test and human relevance review are separate.

**Subscription readiness:** the user confirmed the existing Workers Paid plan used by Databull on the same account. Its $5/month base is shared; no additional subscription is required for this Worker. Check plan readiness before public launch or if moving accounts, and measure incremental usage separately. Preserve Databull and account billing settings. Public launch and the MCP website page remain behind their existing release gates. Uploaded reference images are deferred to the unscheduled future backlog.

## Inspora Pro accounting (not enabled in any deployment)

The Worker owns no billing state. With `MCP_ACCESS_POLICY=pro`, `PRO_ACCOUNTING_URL` (the website's `/api/internal/pro/mcp-usage`) and secret `PRO_ACCOUNTING_TOKEN`, every protected tool call checks current entitlement through the shared Pro service. Only a fresh `search_inspiration` that returns at least one work settles one credit. Continuation, `get_work`, `get_works`, `catalog_status`, empty results and failures are free. Pro clients receive a signed, user-bound `Mcp-Session-Id` during initialization and must send it on subsequent requests. Request IDs and arguments identify retries within that session; another client/session starts a distinct operation. Results are cached for 10 minutes, with fresh entitlement/balance checks and recovery of lost settlement responses. Expired receipts never turn an already settled operation into a free new search. `MCP_ACCESS_POLICY=pro` fails closed unless accounting is configured. The default team-trial policy remains unchanged.

Pro-policy tool calls are limited to 30 per minute and 500 per day across clients, with retry timing. Paid accounts and the team trial have a separate HTTP abuse ceiling of 60 per minute and 1,000 per day; unpaid Pro-policy accounts keep 30 per minute and 500 per day. A short cached classification affects only this HTTP ceiling; it never authorizes access or spending.

## Team allowlist and offboarding

Consent is checked against the website's MCP allowlist only when a client connects; refresh tokens stay valid for up to 30 days. The Worker secret `TEAM_USER_IDS` (comma-separated `user_…` IDs) also checks membership on every authenticated call; set it with `wrangler secret put TEAM_USER_IDS --config <release config>` so deploys keep it. Unset or blank keeps the current behaviour; a malformed list fails closed with 503; non-members receive 403 `TEAM_ACCESS_REQUIRED`.

To onboard someone, add their ID to the website allowlist and to `TEAM_USER_IDS`; a member missing from the secret signs in but gets 403 on every call. To offboard someone: remove them from the website allowlist (blocks new consent) and from `TEAM_USER_IDS` (blocks existing tokens on their next call). `wrangler secret put` replaces the whole list, so send every remaining ID; it takes effect without a redeploy. To also delete their grants, list `grant:<userId>:` keys in the OAuth KV namespace and delete each grant and its `token:<userId>:<grantId>:` keys, or call the provider's `revokeGrant`.

## Observability

Setting `MCP_OBSERVABILITY=minimal` logs one identity-free JSON line per tool call (`tool`, `outcome` code, `ms`; no user, query or arguments). Logs are kept only when Workers Logs is enabled for the Worker, which needs no new provider resource on the Workers Paid plan but is a configuration change: `observability: {enabled: true, logs: {invocation_logs: false}}` in the release configuration (invocation logs would add request metadata). The committed `wrangler.jsonc` keeps observability off.
