# 01: Read eligible website archives through the public-work module

**What to build:** Visitors browsing website archives receive usable, publicly eligible websites through a cohesive server-only public-work reads module. This first vertical slice establishes the shared boundary by moving real selection and card assembly behind it and routing the existing website archive through it.

**Blocked by:** None (can start immediately).

**Status:** ready-for-agent

**Source:** [Public-work reads spec](../spec.md).

- [ ] The module privately owns collection selection, publication and presentation eligibility, ordering, usable card assembly, and eligibility-sensitive caching. The website archive adapter delegates actual selection; the module is not a facade over unchanged repository queries. Any necessary helper extraction happens first within this slice, preserves unrelated consumers, and avoids import cycles.
- [ ] Establish the work-page contract with discriminated scope, supported filters/order, optional opaque cursor, usable cards, and nullable continuation. Subsequent tickets extend this same boundary with their scopes, counts, and identities. Do not expose rows, predicates, arbitrary query callbacks, storage adapters, or caller check-then-map obligations. Reject unsupported combinations rather than silently ignoring them.
- [ ] Capture one internal evaluation time per database read. Published status and a non-null publication time at or before that time are required. Apply scope, publication, website completeness, and supported filters before ordering, limits, or aggregation; media and section joins cannot multiply work.
- [ ] Website completeness requires a recording, nonempty poster, non-null video preview, favicon, at least one section, and nonempty image URL plus present, nonzero dimensions for every section. SQL NULL and JSON null previews are excluded. Retained full-page screenshots do not disqualify a complete recording presentation. Preserve stored-metadata rules without network probes, stronger preview-shape validation, or new media publication rules.
- [ ] Select candidates and hydrate card dependencies in one database statement. Map without separate card loads, a new evaluation time, or silent omission. Unexpected query or mapping inconsistencies fail the read. Document driver evidence and a bounded alternative before departing from statement-level consistency.
- [ ] Preserve website archive publication-time/ID descending order, featured selection, card payloads, media ordering, creator presentation, and public routes. Existing complete-array consumers receive every eligible website through the page result with a null cursor, without new browser pagination. Existing client-side archive controls stay outside the boundary.
- [ ] The module owns public caching with the existing 300-second stale, 21,600-second revalidation, and 604,800-second expiry settings and existing dependency tag strings. Website archive dependencies include its published-work kind and creator presentation. No outer adapter cache can outlive module invalidation; scheduled publication retains existing cache revalidation semantics.
- [ ] The adapter preserves an empty website archive only for explicit no-database configuration. Configured database and integrity failures propagate through existing errors and never become cached empty success.
- [ ] Use an internal deterministic clock and reusable isolated fixtures suitable for later mixed-work tickets. Real PostgreSQL coverage proves completeness is applied before limits and agrees with the in-memory integrity check. Cover each missing/empty/null completeness field independently, one incomplete section among complete sections, legacy screenshots, and publication boundaries, drafts, and archived work. Use virtual rows for schema-rejected cases without weakening constraints.
- [ ] A controlled concurrent presentation edit produces a coherent before/after read or an error, never a successful result with a selected website silently removed. Inject query and mapping failures to establish this contract.
- [ ] Focused archive checks verify full collection shape/order, featured selection, payloads, and fallback. Verify cache-tag wiring and demonstrate an existing invalidation refreshes the website archive in a focused preview runtime check; report that check as unverified if unavailable.
- [ ] Work stays on preview, with no deployment, production/main changes, migrations, backfills, indexes, or persisted eligibility flags. Record concrete query/constraint evidence before proposing any schema change. Detail reads, adjacent navigation, slug enumeration, downloads, and mutation workflows remain outside this interface.
- [ ] Validate only the new interface and directly affected website archive cases, type checking, and linting of changed code. Real database fixtures use established preview fingerprint safeguards and isolated UUID setup/cleanup. Report unavailable real-database or runtime verification explicitly; mocks alone are not parity or consistency proof.
