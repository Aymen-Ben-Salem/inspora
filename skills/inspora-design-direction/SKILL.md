# Develop a design direction

Use this skill for requested guidance, including natural requests such as "help me figure out a visual direction." Deliver the requested comparison, brief or implementation using the project's context and references. A search request, project description or selected reference alone is not a request to begin a consultation.

## Resolve meaningful choices together

Start from what the conversation already establishes. Ask only when plausible answers would change the next search, recommendation or implementation. Skip settled or reasonably clear details. Audience is optional, not an opening step; explore it only when a real distinction would change the design decision.

When a question is useful, ask one focused question at a time in everyday language. Offer choices only when they represent meaningful alternatives supported by the brief or references, and leave room for the user's own answer. Avoid inventing audience segments to populate a menu. Apply each answer, then check whether another unresolved choice would materially shape the next deliverable. Follow up on that choice before committing to it; one answer does not settle unrelated decisions. Let the remaining decisions determine the number of questions, and stop once there is enough direction for the requested next step.

Guidance can begin with useful references and a comparison. When preferences are still open, help the user react to concrete examples rather than requiring an abstract interview. Handle minor details with reasonable defaults. For consequential choices still open, recommend an option with a brief reason and invite the user's choice. If the user asks you to decide, make the recommendation and state its assumptions without adding approval steps.

Explain concrete observations, practical tradeoffs and the reason for a recommendation. Keep enough detail for an informed choice. Use design terminology when it adds precision, with a short plain-language explanation when needed. Use commas or separate sentences instead of em dashes. Match depth to the request; avoid repeated recaps and scripted acknowledgments between questions.

## Understand the references

A website hero supports observations about the visible hero. Treat lower sections, blank product windows and cropped controls as unverified until a separate image shows them. For motion, check which frames the response actually attached before describing a transition.

Inspect shortlisted works using `get_works` when available or `get_work` with `preview=image`. For a motion reference that informs a build, request `get_work` with `detail=study` when supported. Read `preview.study`: when `available` is true, use the sheet timestamps for observed states and label any proposed timing between samples; when it is false, treat the motion as description-only and say so. Identify description-only evidence and missing or unreadable images.

Compare the qualities that matter to this project, such as hierarchy, composition, typography, density or interaction. Explain the practical tradeoffs and credit each reference with its creator and Inspora link. Distinguish observations from proposed adaptations. Verify exact font and technology claims from the source.

When offering alternative visual directions, illustrate each with two relevant linked Inspora examples and explain the supported qualities to borrow from each. Reuse selected or previously shown works where they fit. Exclude work that conflicts with the project's requirements; a caveat cannot turn an unsuitable reference into a recommendation. Show fewer examples or leave a direction unsupported when evidence is scarce; fetch more only when the missing evidence would help the user choose.

When sourcing a direction, consider useful design entries alongside websites and identity work. Separate up to 10 direct subject/use-case references from up to 5 adaptation references when direct coverage is sparse. Honor the user's counts and exact-only constraints. For adaptations, prefer nearby domains or shared functions and show what to borrow, how it serves this project and its scope limit. Inspect uncertain visual compatibility; a shared color or generic headline treatment alone is insufficient. Keep each group's shortage visible rather than filling it with weak references.

Develop the user's stated preferences. Ask about an unresolved priority only when it would change the comparison. Explain the basis of a requested recommendation and leave other directions open.

## Make the direction usable

For a brief, translate useful reference qualities into an original composition for the user's content and constraints. Resolve the decisions needed for the next step, including relevant layout, typography, color roles and interaction states. Connect proposals to the user's goals and their supporting references.

For implementation, follow the project's existing workflow and conventions. Search again when a concrete evidence gap or a requested change of direction warrants it.

Ask a closing question only when it unlocks a meaningful next decision or step. A completed deliverable can stand on its own.
